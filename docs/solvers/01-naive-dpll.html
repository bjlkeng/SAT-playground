01 naive-dpll

This is the first working baseline in the repo: a straightforward DPLL solver with unit propagation, recursive branching, backtracking, and DRAT proof output for UNSAT cases. The point of this iteration is not to be fast; it is to make the core SAT search loop small enough to read end-to-end.

Unit propagation to fixpoint Recursive branch / backtrack DRAT proof output

What It Implements

  • Repeatedly simplify the formula with unit clauses until either a conflict appears or no more forced assignments remain.
  • Pick the first unassigned variable and recurse on the positive branch, then the negative branch if needed.
  • Return a satisfying assignment when every clause is satisfied, or UNSAT when every branch conflicts.
  • Emit an empty-clause DRAT proof for UNSAT so the result still matches the SAT Competition interface.

High-Level Pseudocode

solve(formula, assignment):
  propagate units until fixed point
  if a clause becomes false:
    return UNSAT

  if every clause is satisfied:
    return SAT with assignment

  variable = first unassigned variable

  if solve(formula, assignment ∪ {variable = true}) is SAT:
    return SAT

  return solve(formula, assignment ∪ {variable = false})

Code-Level Optimization Diffs

The README for this solver has a longer benchmark log. These are the highest-signal optimizations that materially changed runtime without changing the algorithm.

Hot Clause Scan

The biggest win was removing a heap allocation from the clause-state helper that ran millions of times in the inner loop. 

- allocate a fresh Vec of unassigned literals on every clause scan
- keep scanning even after discovering 2+ unassigned literals
+ track only a counter and the first unassigned literal
+ return early as soon as the clause is known to be non-unit

Compact Assignment Representation

Assignment values moved from `Option<bool>` to a small `u8` encoding, paired with aggressive inlining in the hot path. 

- Vec<Option<bool>> assignments with small helper calls
+ Vec<u8> with UNASSIGNED / TRUE / FALSE constants
+ inline hot literal-value and assignment helpers

Less Allocation Around The Search

Clause and trail storage were tightened to avoid extra capacity fields and repeated reallocation during recursion. 

- Vec<Vec<i32>> clauses and growth-by-use trail buffers
+ Vec<Box<[i32]>> immutable clause storage
+ preallocated trail and parser buffers reused instead of cloned
