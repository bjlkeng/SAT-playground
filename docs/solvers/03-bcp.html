03 bcp

This iteration keeps the same CDCL structure as 02, but replaces full-clause-scan propagation with watched-literal Boolean constraint propagation. The main idea is to revisit only clauses affected by newly falsified literals instead of rescanning the whole formula after every assignment.

What It Implements

  • Two watched literals per non-unit clause, plus per-literal watch lists so propagation touches only relevant clauses.
  • A `propagate_head` over the trail, which means only newly assigned literals trigger watch-list processing.
  • The same learned-clause, reason-clause, and non-chronological backtracking machinery introduced in `02`.
  • Explicit handling for root-level unit clauses and empty clauses before the main search loop starts.

High-Level Pseudocode

initialize watch lists for all clauses
enqueue any root-level unit clauses

loop:
  while propagate_head < trail.len:
    lit = trail[propagate_head]
    propagate_head += 1

    for clause watching the now-false literal:
      if other watched literal satisfies clause:
        keep watches
      else if another non-false literal exists:
        move the watch
      else if other watched literal is unassigned:
        enqueue implied literal
      else:
        return conflict

  if conflict:
    analyze, learn, backjump, assert learned literal
  else if all variables assigned:
    return SAT
  else:
    make next decision literal

Code-Level Optimization Diffs

The README has the full tuning log. These are the changes that most materially altered `03` on the profiling suite.

Watch-List Hot Path

Propagation moved away from repeated temporary allocations and toward a reusable scratch list plus pointer-based clause scans. 

- fresh retained-watch vectors and indexed scans in propagate()
+ reusable watch_scratch buffer
+ pointer-backed watched-clause traversal in the inner loop

Ternary-Clause Fast Path

The profiling suite is dominated by binary and ternary clauses, so `03` added a special-case path for length-3 clauses instead of falling through to the generic replacement-watch search every time. 

- treat ternary clauses like the generic N-literal case
+ dedicated len == 3 propagation path
+ less branchy watch replacement on Feistel-heavy inputs

Root-Level State Fix

The biggest win was fixing `backtrack(0)` so root-level assignments survive a jump back to decision level 0. On the crypto CNFs, clearing those assignments destroyed useful search state and caused repeated timeouts. 

- backtrack(0) clears level-0 assignments along with decision assignments
+ track root_trail_len separately
+ preserve root implications when jumping back to level 0

Phase-Saving Rollback

`03` briefly gained a polarity-memory heuristic, but the final tuned version removed it because the harder Feistel cases improved without the extra phase state. 

- save and reuse the last seen polarity for each variable
+ revert to simpler sign behavior in the tuned version
+ lower overall PAR-2 on the profiling and crypto suites
