10 bve-preprocess

This iteration keeps 09's optimized CDCL core and adds a MiniSat SimpSolver-style preprocessing front end. Solver 10 canonicalizes input clauses, performs backward subsumption and bounded variable elimination before search, logs preprocessing proof steps, and extends SAT models back through eliminated variables.

What It Implements

  • The same watched-literal propagation, EVSIDS branching, restarts, learned-clause reduction, root simplification, proof streaming, and optimized hot paths from 09.
  • Parse-time clause normalization that removes duplicate literals, skips tautologies and already-satisfied clauses, enqueues root units immediately, and feeds surviving clauses through the same path used by preprocessing-generated clauses.
  • MiniSat-style preprocessing state: original-clause occurrence lists, literal occurrence counts, a separate decision-variable flag, touched-variable queues, subsumption queues, and a dynamic elimination heap.
  • Backward subsumption and self-subsuming resolution over original clauses, including in-place strengthening and proof metadata updates for strengthened clauses.
  • Bounded variable elimination with grow = 0 and clause_lim = 20, plus resolvent insertion through the original-clause path so new resolvents can immediately participate in more subsumption work.
  • A MiniSat-style elimination stack and SAT model-extension pass, so removed variables are reconstructed before emitting a complete model.
  • Large-formula preprocessing optimizations, including inline original-clause abstractions, lazy occurrence-list cleanup, sorted-clause relation checks where safe, and targeted watcher-detach policies.

High-Level Pseudocode

parse clauses through the preprocessing original-clause path
enqueue root units, skip tautologies, and build occurrence lists

if simplification is enabled:
  initialize touched variables, subsumption queue, and elimination heap

  while preprocessing work remains:
    propagate root assignments
    run backward subsumption on queued clauses
    strengthen original clauses when self-subsuming resolution applies
    pick a low-cost variable from the elimination heap
    if all resolvents fit the bounded-elimination budget:
      delete clauses containing the variable
      add resolvents and proof steps
      push an elimination-stack entry for model reconstruction
    update occurrence costs and enqueue newly touched clauses

  drop preprocessing metadata, rebuild the branch heap, and compact the arena

run the solver 09 CDCL search core on the residual formula

if SAT:
  extend the model through the elimination stack
  print the completed model
if UNSAT:
  finalize the combined preprocessing and search proof

Code-Level Optimization Diffs

The README and MiniSat port notes have the full benchmark history. These are the changes that best explain how 10 differs from 09.

Preprocessing Metadata

Solver 09 searched the parsed formula directly. Solver 10 builds temporary occurrence metadata so it can run simplification before search and then discard that state. 

- enter CDCL search immediately after root simplify
+ build occurrence lists, occurrence counts, and elimination heap
+ drop preprocessing metadata before the residual CDCL solve

Backward Subsumption

Backward subsumption deletes clauses made redundant by smaller clauses and strengthens originals when self-subsuming resolution can remove a literal. 

- keep every surviving original clause unchanged before search
+ queue original clauses for backward subsumption checks
+ strengthen clauses in place and update proof metadata

Bounded Variable Elimination

Variables are eliminated only when the generated resolvents fit MiniSat's bounded growth policy. This can shrink the residual formula without exploding clause count. 

- every parsed variable remains a CDCL decision candidate
+ mark eliminated variables as non-decision variables
+ insert resolvents and push model-extension stack entries

Large-Formula BSR Hot Path

Later optimization passes kept the algorithm but changed the data path: abstractions live inline with original clauses, strengthening is compacted in one pass, and dirty occurrence lists are cleaned lazily. 

- scan large formulas through sparse side-table metadata
+ store original-clause abstractions inline during preprocessing
+ reuse scratch buffers and lazily clean occurrence membership

Benchmark Role

Solver 10 is the first repo solver that seriously targets MiniSat simp-style preprocessing rather than only CDCL search mechanics. On the MiniSat-simp five-instance set, the accepted gated-BSR run solved all five formulas and moved PAR-2 from solver 09's 3195.921 to 540.550, close to MiniSat simp's 453.343 on that same harness.

On the 100-instance SAT Competition 2025 medium site run, the latest available solver 10 artifact solves 47/100 with PAR-2 204961.832, compared with solver 09's 46/100 and PAR-2 208534.668. That run still records four memory-abort errors, so its role is best read as an improved but not fully hardened medium benchmark baseline.
