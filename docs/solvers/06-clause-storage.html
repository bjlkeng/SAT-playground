06 clause-storage

This iteration keeps the CDCL + restart core from 05, but rewrites clause storage and propagation around a MiniSat-style watcher layout. Watched literals now live directly in clause slots 0 and 1, watcher entries carry a cached blocker literal, and propagation runs the standard blocker fast path plus in-place watch swapping. Because clause bodies mutate in place, learned clauses are copied when they enter the proof log so DRAT output stays stable.

What It Implements

  • The same CDCL conflict analysis, learned clauses, restarts, saved phases, and heap-based branch selection already introduced in 05.
  • Watched literals stored directly inside each clause body, with the active watched pair normalized into slots 0 and 1.
  • Watcher-list entries that store both the clause id and a blocker literal, so satisfied clauses can often skip the more expensive clause-body scan.
  • Copied proof logging for learned clauses so in-place watch swaps do not mutate previously emitted DRAT clauses.

High-Level Pseudocode

initialize CDCL state from solver 05
store watched literals directly in clause slots 0 and 1
store watcher entries as { clause_idx, blocker }

loop over falsified trail literals:
  for watcher in watchers[false_lit]:
    if blocker is already satisfied:
      keep watcher and continue

    normalize the falsified watched literal into clause slot 1

    if clause[0] is satisfied:
      update blocker to clause[0]
      keep watcher and continue

    search clause[2..] for a replacement watched literal
    if replacement exists:
      swap it into slot 1
      move the watcher to the replacement literal's watch list
      continue

    if clause[0] is unassigned:
      enqueue clause[0] as a unit implication
    else:
      return conflict

Code-Level Optimization Diffs

The README has the longer storage-rewrite notes. These are the implementation changes that best summarize how `06` differs from `05`.

Clause-Body Watch Layout

The watched-literal state moved out of side metadata and into the clause body itself so the propagation path can treat slots 0 and 1 as the active watch pair. 

- keep watch positions in a separate watch_pos structure
+ store the watched literals directly in clause slots 0 and 1
+ swap clause literals in place when a new watch is found

Blocker-Based Propagation

Watcher lists now cache a blocker literal so satisfied clauses can exit early before touching most of the clause body. 

- watcher lists store only bare clause ids
+ watcher entries store { clause_idx, blocker }
+ use the blocker fast path before scanning clause[2..]

Proof Logging By Copy

Because watch maintenance mutates clause bodies in place, proof logging had to stop aliasing the live solver storage. 

- reuse live learned-clause storage for proof output
+ copy learned clauses into the proof log on insertion
+ keep DRAT output stable even while watched literals move
