04 vsids

This iteration keeps the watched-literal CDCL core from 03, but replaces the static branch order with a conflict-driven activity heuristic in the style of VSIDS / EVSIDS. Variables touched by conflict analysis get bumped, older conflicts decay away, and the next decision comes from a heap-backed priority queue instead of a linear first-fit scan.

What It Implements

  • The same watched-literal propagation, reason clauses, learned clauses, and non-chronological backtracking already introduced in 03.
  • A floating-point activity score for every variable, bumped when the variable appears in conflict analysis and decayed over time so recent conflicts matter more.
  • An indexed heap that always returns the highest-activity unassigned variable for the next branch decision.
  • A stable occurrence-order tie-break carried over from 03 so equal-activity variables still branch deterministically.

High-Level Pseudocode

initialize watched-literal CDCL state
initialize activity scores and branch heap

loop:
  conflict = propagate_over_trail()

  if conflict exists:
    if decision_level == 0:
      return UNSAT

    learned_clause, backjump_level, analyzed_vars = analyze_conflict(conflict)
    bump activity for analyzed_vars
    decay future bump amount
    add learned_clause to the database
    backtrack(backjump_level)
    enqueue asserting literal
    continue

  if every variable is assigned:
    return SAT

  variable = highest-activity unassigned variable from heap
  enqueue decision literal(variable)

Code-Level Optimization Diffs

The README contains the full tuning history. These are the implementation-level changes that most clearly define the current `04` branch-selection path.

Heap-Backed Decisions

The key structural change was moving from a static branch scan to an indexed heap keyed by variable activity. 

- walk a fixed branch-order array to find the next unassigned variable
+ maintain an indexed heap of candidate variables
+ pop the highest-activity unassigned variable at each decision

Analysis-Time Activity Accounting

Conflict analysis now explicitly tracks the variables it touched so the EVSIDS updates happen once per analyzed variable, not via ad hoc rescans. 

- static branching with no conflict-driven signal
+ collect analyzed variables while walking reason clauses
+ bump activity after learning, then decay the future bump amount

Tighter Activity-State Footprint

The tuning log shows the activity path getting smaller and denser so the heuristic stays cheap enough to use on every conflict and decision. 

- f64 activity values and wider branch-order storage
+ f32 activity values for better cache density
+ narrower branch-order bookkeeping and less hot-path memory traffic
