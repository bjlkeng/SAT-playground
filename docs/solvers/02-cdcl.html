02 cdcl

This iteration switches from plain recursive DPLL to conflict-driven clause learning (CDCL). Instead of blindly flipping the most recent decision, the solver analyzes conflicts, learns a clause, and jumps directly back to the most useful earlier decision level.

Back To Main Page Solver Source Optimization Notes
Learned clauses Decision levels + reason clauses Non-chronological backtracking

What It Implements

  • Explicit trail-based state instead of recursive calls, with a decision level recorded for every assignment.
  • Full-clause-scan propagation to fixpoint, which keeps the control flow easy to follow before watched literals are introduced later.
  • Conflict analysis that resolves backward through implication reasons until the first UIP cut leaves exactly one current-level literal.
  • Backjumping to the highest useful earlier decision level, then asserting the learned clause immediately.

High-Level Pseudocode

initialize original clause database
decision_level = 0

loop:
  conflict = propagate_until_fixpoint()

  if conflict exists:
    if decision_level == 0:
      return UNSAT

    learned_clause, backjump_level = analyze_conflict(conflict)
    add learned_clause to the database
    backtrack(backjump_level)
    enqueue asserting literal from learned_clause
    continue

  if every variable is assigned:
    return SAT with assignment

  variable = next branch variable
  decision_level += 1
  enqueue decision literal(variable)

Code-Level Optimization Diffs

`02` was kept algorithmically simple on purpose. Most of the later speedup came from tightening the CDCL data path rather than changing the search strategy.

Reason Tracking Without `Option`

The solver stopped wrapping every implication reason in `Option<usize>` and switched to a plain index plus a sentinel value for decisions. 

- Option<usize> reason per variable
+ usize reason index with a NO_REASON sentinel
+ less branching and less per-assignment overhead in conflict analysis

Reusable Scratch Buffers

Conflict analysis originally allocated temporary vectors for every learned clause. Those buffers were moved into the solver and reused. 

- allocate seen / resolved / learned vectors on every conflict
+ keep reusable scratch storage inside Solver
+ reduce allocation churn during repeated backjumps

Propagation Hot Path

The propagation loop dropped an extra `ClauseState` layer and scanned clauses directly, then later moved the clause database into a flatter layout for locality. 

- indirect clause-state helper in the inner loop
- boxed clause storage only
+ direct literal scanning inside propagate()
+ flat clause data buffer and lighter clause references

Cheaper Branch Selection

`02` still branches on the first plausible unassigned variable, but it avoids restarting the scan from variable `1` after every decision. 

- restart the branch scan from variable 1 every time
+ keep a branch cursor and reset it only when backtracking requires it
+ same heuristic, less repeated work
