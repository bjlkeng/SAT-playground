SAT Playground · Solver 07

07 clause-minimization

This iteration keeps 06's MiniSat-style watched-clause layout and adds runtime conflict-clause minimization during CDCL analysis. Learned clauses can now be shrunk in basic or deep mode, redundant literals may be removed through recursive reason traversal, and the solver preserves the learned clause's asserting property before enqueueing it after backjumping.

Basic + deep minimization Learned-reason recursion Asserting-clause backjump check

What It Implements

  • The same watched-clause propagation, blocker watchers, learned clauses, restarts, saved phases, and heap-based branch selection from 06.
  • Two conflict-clause minimization modes: basic, which removes literals whose reason clauses depend only on already-kept sources, and deep, which recursively walks the reason DAG.
  • Learned-reason recursion during deep minimization, not just recursion through original clauses.
  • Conflict-analysis invariants that preserve an asserting learned clause after backtrack, including a debug check that the head literal is unassigned and the rest are false.
  • An environment override, SAT_CCMIN_MODE=none|basic|deep, for benchmarking and debugging.

High-Level Pseudocode

conflict = propagate()
if conflict exists:
  learned_clause, backjump_level = analyze_conflict(conflict)

  if ccmin_mode == basic:
    remove literals whose reason parents are all already sourced
  else if ccmin_mode == deep:
    recursively walk reason clauses and remove literals proven redundant

  add learned_clause to the database
  backtrack(backjump_level)
  assert learned_clause is still asserting
  enqueue learned_clause[0] with the learned clause as its reason

Code-Level Optimization Diffs

The README has the full notes. These are the implementation changes that best summarize how 07 differs from 06.

Conflict-Clause Shrinking

Conflict analysis no longer emits the raw first-UIP clause unconditionally. It now runs an explicit redundancy pass before the learned clause enters the database. 

- learn the raw first-UIP clause directly
+ run basic or deep redundancy checks before adding the clause
+ drop literals whose reasons are already covered by the learned source set

Learned-Reason Recursion

Deep minimization can recurse through learned reasons as well as original ones, but it has to skip the reason-clause head by slot and ignore level-0 parents. 

- stop deep minimization at learned-clause reasons
+ recurse through learned reasons too
+ skip reason_clause[0] and ignore decision-level-0 parents

Asserting-Clause Preservation

Backtracking had to preserve the target level exactly so the minimized clause still becomes unit at the backjump destination. 

- backtrack based only on the previous decision-level boundary
+ preserve trail_limits[target_level] when backjumping
+ debug-assert that the learned clause is still asserting after backtrack

Proof Caveat

The solver's runtime minimization is more aggressive than its proof bookkeeping. The DRAT output still records only the minimized learned clause, not an explicit strengthening chain, so 07 keeps the solver-side wins from clause minimization without yet turning that proof path into a fully explicit proof-side minimizer.
