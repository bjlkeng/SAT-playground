11 kissat-search

This iteration keeps solver 10's MiniSat SimpSolver-style preprocessing baseline and ports a Kissat-style search engine on top of it: a focused/stable dual-mode scheduler, a VMTF decision queue, LBD (glue) clause scoring with tiered reduction, and a suite of optional inprocessing-era refinements, all driven by an explicit configuration and profile system.

What It Implements

  • The full solver 10 baseline: parse-time clause normalization, backward subsumption, bounded variable elimination, model extension, and the optimized 09 CDCL core and proof streaming.
  • A Kissat-style focused/stable dual-mode search: focused mode digs aggressively for conflicts with frequent restarts, while stable mode consolidates with quieter reluctant restarts. A tick-based scheduler switches modes at propagation-bounded boundaries.
  • A VMTF (variable-move-to-front) decision queue used in focused mode, alongside the EVSIDS/VSIDS activity heap used in stable mode.
  • LBD (literal-block-distance) glue scoring for learned clauses, with an LBD-tiered reduce policy that keeps low-glue clauses and recycles high-glue ones.
  • Optional, default-off Kissat-era refinements behind explicit flags: a pre-search lucky pass, guarded chronological backtracking, restart trail reuse, rephasing, on-the-fly subsumption (OTFS), binary-clause fast paths, and software prefetch of the next watched clause.
  • An explicit configuration and profile system (SolverConfig, CONFIG_SCHEMA.csv, a feature-maturity ledger, config hashing, and JSON stats) so every benchmark records exactly which features were active.
  • Config-reserved slots for not-yet-landed inprocessing (vivification, probing, hyper-binary resolution, gate extraction) that are rejected at runtime until their implementation lands, so no benchmark records a no-op flag.

High-Level Pseudocode

run solver 10 preprocessing (subsumption + bounded variable elimination)

optionally run a pre-search lucky assignment probe

mode = focused
while not solved:
  propagate
  if conflict:
    analyze, compute LBD glue, learn clause, record proof step
    backtrack (optionally one-level chronological)
    bump activity (VMTF in focused, VSIDS in stable)
  else if all variables assigned:
    return SAT
  else:
    decide next literal (VMTF queue or activity heap by mode)

  at scheduling boundaries (tick budget reached):
    maybe restart (frequent in focused, reluctant in stable)
    maybe reduce the clause DB by LBD tier
    maybe rephase saved phases
    maybe switch focused <-> stable

if SAT:
  extend the model through the elimination stack and print it
if UNSAT:
  finalize the combined preprocessing + search DRAT proof

Code-Level Optimization Diffs

The README and feature ledger have the full flag-by-flag history. These are the changes that best explain how 11 differs from 10.

Dual-Mode Scheduler

Solver 10 ran a single search mode. Solver 11 overlays a Kissat-style focused/stable schedule, switching at tick-budget boundaries. 

- one fixed restart + decision policy for all of search
+ focused mode: VMTF + frequent restarts to find conflicts
+ stable mode: VSIDS + reluctant restarts to consolidate

LBD Glue + Tiered Reduce

Learned clauses are scored by literal-block distance, and clause-database reduction keeps low-glue clauses while recycling high-glue ones. 

- reduce by clause activity only
+ compute LBD glue on every learned clause
+ keep low-LBD tiers, recycle high-LBD clauses

Optional Search Refinements

A set of Kissat-era refinements ship behind explicit, default-off flags so each can be measured independently before promotion. 

- no lucky probe, rephasing, chrono, or OTFS
+ flagged lucky / rephase / chrono / trail-reuse / OTFS
+ software prefetch of the next watched clause

Config + Profile Governance

Every feature is a typed config field with a maturity record, so benchmark artifacts capture exactly which flags were active and reject reserved no-op flags at runtime. 

- env toggles with no provenance record
+ SolverConfig + CONFIG_SCHEMA + config_hash in stats
+ reserved inprocessing flags rejected until implemented

Benchmark Role

Solver 11 is the repo's first solver to layer a modern Kissat-class search engine on top of MiniSat-style preprocessing. Its default profile (fstab_lbdtier) runs focused/stable search with LBD-tiered reduction.

On the 100-instance SAT Competition 2025 medium site run, solver 11 solves 53/100 (29 SAT + 24 UNSAT) with PAR-2 183013.118, improving on solver 10's 47/100 and PAR-2 204961.832. Its remaining non-solves are honest 16 GB resource limits on very large formulas — two memory-aborts and two memory-preflight UNKNOWNs — plus search timeouts, so it is best read as a stronger but still resource-bounded medium baseline. All of its UNSAT DRAT proofs verify with drat-trim.
