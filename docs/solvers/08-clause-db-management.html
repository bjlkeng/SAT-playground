08 clause-db-management

This iteration keeps 07's conflict-clause minimization and turns the learned-clause store into a managed MiniSat-style database. Clauses now live in one packed arena with stable offset references, learned clauses carry activity scores, database reduction can detach and tombstone low-value learned clauses, and garbage collection relocates live clauses while fixing up watchers and reasons.

What It Implements

  • The same watched-clause propagation, restarts, saved phases, EVSIDS branching, and conflict-clause minimization from 07.
  • A packed word arena for original and learned clauses, with each clause reference represented as a stable arena offset instead of a dense vector index.
  • Inline learned-clause activity storage so the database reducer can keep recently useful clauses and delete low-priority unlocked clauses.
  • MiniSat-style learned-clause reduction thresholds, a dedicated live learned-clause list, and O(1) locked-clause checks through the head literal's reason slot.
  • Garbage collection that compacts live clauses and rewrites watcher entries plus live reason[var] references after relocation.
  • A streamed proof writer that buffers DRAT output to proof.out.tmp before finalizing proof.out on UNSAT.

High-Level Pseudocode

store clauses in a packed arena and use arena offsets as clause refs
initialize watched literals, reasons, learned list, proof stream, and reduction budget

loop:
  conflict = propagate()

  if conflict exists:
    if decision_level == 0:
      finalize UNSAT proof and return UNSAT

    learned_clause, backjump_level, reason_chain = analyze_conflict(conflict)
    minimize learned_clause using solver 07's redundancy checks
    bump activity for learned clauses on the analyzed reason chain
    add learned_clause to the arena and live learned list
    backtrack(backjump_level)
    enqueue learned_clause[0] with the new clause as reason

    if learned database exceeds its conflict-window budget:
      sort learned clauses by activity and size
      detach and tombstone unlocked low-priority learned clauses
      compact arena and fix watcher / reason references when waste is high
    continue

  if all variables are assigned:
    discard temporary proof output and return SAT

  branch on the highest-activity unassigned variable

Code-Level Optimization Diffs

The README has the full benchmark history. These are the implementation changes that best summarize how 08 differs from 07.

Packed Clause Arena

Clause storage moved from split metadata and literal vectors into one arena where the header, literals, and learned activity live together. 

- store clause refs as dense table indices into separate clause vectors
+ store clause refs as stable offsets into a packed word arena
+ keep learned activity inline as the clause's extra arena word

Learned-Clause Cleanup

The solver now has a real deletion path: learned clauses can be detached from watcher lists, removed from the live learned list, and skipped after tombstoning. 

- keep every learned clause for the lifetime of the solve
+ reduce the learned database with MiniSat-style size thresholds
+ skip locked and binary clauses while deleting low-activity learned clauses

Relocation-Safe References

Once deleted clauses create enough arena waste, garbage collection relocates live clauses and rewrites every reference that can still point at them. 

- assume clause storage never moves after insertion
+ compact live clauses during arena GC
+ rewrite watcher clause refs and live reason[var] refs after relocation

Proof Streaming

DRAT output no longer keeps the full learned-clause proof history in memory while the internal solver is free to delete and compact learned clauses. 

- retain proof clauses in memory until the solve finishes
+ stream proof literals through a fixed 16 MiB byte buffer
+ write proof.out.tmp during search and finalize proof.out only on UNSAT

Benchmark Role

On the current medium benchmark data used by the site, 08 is the first iteration where learned-clause database management is active end to end. Its profiling wins came mostly from matching MiniSat's learned-clause activity signal more closely, then tuning how quickly the learned-clause budget grows.
