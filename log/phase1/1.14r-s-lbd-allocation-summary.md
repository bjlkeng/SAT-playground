# Phase 1 LBD Allocation Cleanup Summary

Date: 2026-05-23

Beads:

- `SAT-playground-5b2.2.47` - eliminate per-call `Vec<i32>` allocation in
  `compute_lbd_for_clause`.
- `SAT-playground-5b2.2.48` - eliminate per-call dense delete-vector allocation in
  `reduce_db_lbd_tiered`.

## Work Order

`bv --robot-plan` ranked `SAT-playground-5b2.2.47` as the first ready executable Phase 1 item, and
`SAT-playground-5b2.2.48` was the companion allocation cleanup in the same LBD/reduce-DB throughput
group. `SAT-playground-5b2.2.50` remains higher priority than `.48`, but it is a phase/restart
search-trajectory change rather than part of this allocation group. This pass intentionally stayed
inside Phase 1.

## Implementation

`SAT-playground-5b2.2.47`:

- Split LBD stamping into reusable helpers:
  - `begin_lbd_measurement`
  - `count_lbd_level`
  - `finish_lbd_measurement`
- Kept `compute_lbd_from_lits` for already-materialized literal slices.
- Changed `compute_lbd_for_clause` to walk `clause_len` / `clause_lit` by arena index, avoiding
  `self.clause_slice(clause_idx).to_vec()`.
- Added a test-only counting allocator with thread-local enablement so hot-path allocation tests are
  stable under the parallel Rust test harness.
- Added allocation tests for the clause helper and the conflict-analysis reason path.

`SAT-playground-5b2.2.48`:

- Added persistent LBD reduce scratch:
  - `reduce_delete_generation`
  - `reduce_delete_mark`
  - `reduce_candidates`
- Replaced `vec![false; self.arena.len()]` with generation-stamped delete marks.
- Reused `reduce_candidates` instead of allocating the candidate vector each pass.
- Replaced `std::mem::take(&mut self.learned_clause_ids)` + push-back rebuild with in-place
  compaction by write index.
- Added marker growth, generation wraparound, and no-per-call-allocation tests for the reused marker
  path.

## Fresh-Eyes Review

Review checks:

- Empty LBD inputs still return `0` without advancing the stamp.
- LBD stamp wrap still clears the seen table and resumes at stamp `1`.
- Clause LBD calculation reads one arena literal at a time, so no long immutable arena borrow
  overlaps mutable LBD scratch updates.
- The conflict-analysis allocation test pre-sizes unrelated glue histograms so it isolates the
  intended reason-LBD path rather than counting histogram growth.
- LBD reduce in-place compaction preserves learned-clause order for kept clauses and only truncates
  after the original list has been scanned.
- Delete marks are generation-scoped, grow on arena growth, and are cleared on generation wrap.
- Clause relocation after GC is safe because delete marks are ignored after the generation advances.

Fix found during review:

- The first broader conflict-analysis allocation test counted two unrelated histogram vector grows.
  The test now pre-sizes both focused and stable glue histograms before enabling allocation counting.

Interpretation:

- Search counters are identical across the three runs: conflicts, propagations, decisions,
  reductions, learned collections, and LBD improvements match exactly for completed rows.
- The change is therefore behavior-preserving for this mode on completed rows; the measured win is
  local throughput only.
- The final combined patch improves completed-row search time by `1.987s` and PAR-2 by `1.849s`
  versus the original before run.
- The gain is small relative to single-run benchmark noise, but the direction matches the intended
  allocation cleanup and there is no same-mode status regression.

Default-off baseline comparison:

- Baseline: `log/phase1/1.16-phase-legacy-counter-profile-after`, 11/11 solved, PAR-2 `635.922`.
- Final LBD reason-update mode: 10/11 solved, PAR-2 `1121.274`.
- Status regression remains: `mp1-Nb7T46` is SAT in `42.349s` in the default-off baseline and
  timeout in the LBD reason-update mode.

Conclusion:

The allocation bugs are fixed and validated, but these fixes do not make the LBD-tiered
reason-update profile promotable. The residual profile gap is not caused by changed search
trajectory in these allocation patches; it remains a separate LBD-tiered/reason-update mode issue.
