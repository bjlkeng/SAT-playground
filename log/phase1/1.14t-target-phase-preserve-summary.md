# 1.14t target phase restart preservation

Date: 2026-05-23
Bead: `SAT-playground-5b2.2.50`
Solver: `solver/11-kissat-port`

## Selection

`bv --robot-plan`, `bv --robot-triage`, and `bv --robot-insights` all left the Phase 1 gate
blocked by open search-throughput work. The next high-value executable bead was
`SAT-playground-5b2.2.50`, a P2 phase-saving/restart bug that blocks re-running the focused/stable
phase matrix in `SAT-playground-5b2.2.46`.

## Implementation

- Added `Solver::preserve_target_phase_across_restart()`.
- `perform_restart_if_pending()` now preserves `target_phase` only under
  `SAT_SEARCH_MODE=focused-stable`; single-mode target policies keep the previous restart-time
  target reset behavior.
- `apply_rephase()` now calls `reset_target_phase()` so a rephase starts a new target-phase block
  instead of letting stale target choices override the newly cycled saved phase.
- Updated solver README/state/features documentation to state the focused/stable boundary and the
  rejected all-mode experiment.

Examples:

- Single mode with `SAT_PHASE=target-then-saved`: a restart clears `target_phase`, matching the
  previous profile behavior.
- Focused/stable mode with `SAT_PHASE=target-then-saved`: a restart preserves `target_phase`, so
  the target prefix can span restart cycles until a rephase starts a new block.
- Any rephase event clears `target_phase` after cycling saved phase through best/inverted/original.

## Fresh-eyes review

The first implementation removed the restart reset for every search mode. Unit tests passed, but
the 11-instance target-phase profile showed severe search-path regressions. This made the original
all-mode interpretation non-promotable:

- Before: `log/phase1/1.14t-target-phase-preserve-profile-before`
- All-mode after, rejected: `log/phase1/1.14t-target-phase-preserve-profile-after`
- Settings: `SAT_PHASE=target-then-saved SAT_STATS_JSON=on SAT_TRACE_FULL=on`, 11 profiling
  instances, 300s timeout, 16 GiB memory.
- Result: 9/11 solved, PAR-2 1642.134 -> 7/11 solved, PAR-2 2614.777.
- New timeouts: Timetable and REGRandom K4.

The final patch narrows restart preservation to focused/stable search, which is the downstream
matrix this bead needs to unlock, and keeps single-mode target policy behavior unchanged.
