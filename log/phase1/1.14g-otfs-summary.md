# Phase 1.14g OTFS Summary

Bead: `SAT-playground-5b2.2.28`

## Selection

`bv --robot-plan`, `bv --robot-triage`, and `bv --robot-insights` showed the
next ready Phase 1 critical-path bead was 1.14g OTFS. It directly unblocks the
Phase 1 integration checkpoint and later on-the-fly strengthening work, while
higher-priority integration beads were still blocked.

## Implementation

- Added `SAT_OTFS=on|off` as an explicit experimental config flag (`otfs`) with
  replay, config hash, strict-env, schema, feature-ledger, and docs coverage.
- Added a bounded search-time OTFS pass after learned-clause recording:
  - active only when `SAT_OTFS=on` and clause minimization is not off;
  - learned clause length cap: 20 literals;
  - candidate cap: candidate length <= learned length + 4;
  - scans watcher lists for learned literals;
  - deletes only live learned clauses subsumed by the new learned clause;
  - skips the current learned clause, original clauses, deleted clauses, and
    learned clauses currently used as reasons;
  - emits a DRAT deletion before tombstoning a subsumed learned clause.
- Added OTFS stats to JSON and full trace:
  `otfs_watch_scans`, `otfs_candidate_checks`, `otfs_subsumed_clauses`,
  `otfs_subsumed_learned`.
- Added focused tests for default-off behavior, learned-clause deletion,
  non-subsumed clauses, original-clause preservation, proof deletion logging,
  and live reason-clause protection.

## Fresh-eyes review findings

The initial implementation allowed original clauses to be deleted during search
OTFS. The first enabled profile caught this as a SAT model failure on the
Timetable instance, with `otfs_subsumed_original=2390` in the failed trace. That
attempt was rejected, and the implementation now deletes learned clauses only.

The learned-only enabled implementation was correctness-clean but slower on the
profiling suite. It was therefore gated behind `SAT_OTFS=on` and left
Experimental/default-off. A follow-up review also filtered original clauses
before OTFS candidate accounting so enabled runs do less unnecessary candidate
work.
